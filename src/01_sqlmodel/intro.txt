===============================================================================================

SQLModel is a library for interacting with SQL databases from Python code, with Python objects. 
It is designed to be intuitive, easy to use, highly compatible, and robust.

In standard backend architecture, developers suffer from the "dual-schema" problem. You write a 
strict Pydantic BaseModel to validate incoming JSON payloads at your API boundary. Then, you write 
an almost identical SQLAlchemy Model to save that exact same data to your database. When a business 
requirement changes, you must update both files and keep them perfectly in sync to prevent your 
application from crashing.

SQLModel eliminates this duplication. It allows you to write a single Python class that acts as both 
a Pydantic validation firewall and a SQLAlchemy ORM (Object-Relational Mapping) model. You define your 
data shape once, and the library handles both API parsing and database communication


Why SQLModel is the Modern Standard?

- SQLModel is not a brand-new ORM built from scratch. Under the hood, it is literally Pydantic and 
  SQLAlchemy fused together. When you instantiate a model, it uses Pydantic's Rust-powered parsing 
  engine. When you run a database query, it uses SQLAlchemy's battle-tested SQL execution. You get 
  the massive ecosystem and stability of both tools.

- Because SQLModel relies entirely on standard Python type hints rather than dynamic metaclasses, 
  your IDE provide perfect autocomplete. The types you write are exactly the types your database returns.

- SQLModel provides a simple configuration flag (table=True). If set to true, the class translates into 
  a physical table in your database. If omitted, it acts purely as a standard Pydantic model for API 
  validation. This allows you to inherit and share data shapes across your entire stack effortlessly.


The Three-Stage Database Workflow

- The Definition (The Contract): You subclass SQLModel and define your columns using Python type hints. 
  You use the Field() function to declare database-specific constraints, like defining a primary_key or 
  establishing foreign keys.

- The Engine (The Connection): You create an Engine, which manages the physical connection pool to your 
  Postgres, MySQL, or SQLite database.

- The Session (The Workspace): You open a Session to interact with the database. You use standard Python 
  syntax to query, add, modify, or delete your typed objects, and the Session translates your Python code 
  into highly optimized raw SQL queries behind the scenes.
